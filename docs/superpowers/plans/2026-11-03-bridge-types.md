# Generated bridge types Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every type, command, event and error code that crosses the bridge is written once in C#, and the page's
TypeScript for it is generated and checked.

**Architecture:** A console tool (`tools/MoonwellEditor.BridgeTypes`) asks the bridge's own `JsonSerializerOptions`
what each type looks like when written (names, nulls, enum text) and writes `web/src/lib/bridge.gen.ts` with the C#
docs. The app's commands become a static table of entries (name, argument record, answer type, handler), which both the
bridge and the generator read; events become a typed list. A C# test fails when the committed file is out of date.

**Tech Stack:** .NET 10, System.Text.Json (contract API: `JsonTypeInfo`, `JsonPropertyInfo`, `JsonParameterInfo`),
xunit 2, Svelte 5 + TypeScript, svelte-check, vitest, Biome.

**Spec:** `docs/superpowers/specs/2026-11-03-bridge-types-design.md`

## Global Constraints

- No new NuGet or npm package.
- What goes over the wire does not change: command names, argument names, answer fields and values, event names. Only
  a `badRequest`'s message may change.
- `TreatWarningsAsErrors`, nullable on, XML docs on public types in the house tone (plain, short, "the page", "the
  app"). Comments only where the code cannot say it.
- Every enum on the bridge writes exactly today's text; `ThingKind` keeps PascalCase (`StartLocation`).
- The game-data cache file and the map files keep their format (`GameData`'s `FieldInfo.Asset` stays a string).
- Before `dotnet build` or `dotnet test`, check `Get-Process dotnet`; add `-m:4` when other runs are going. Run only the
  area's tests while building; the full suite once, in Task 9.
- File split with the Photino host session: it owns `MainForm.cs`, `TitleBar.cs`, `PageOrigins.cs`, `Program.cs`, the
  App csproj, `webview()` in `bridge.ts` and `env.d.ts`. This plan touches `MainForm.cs` only to change its `Notify`
  calls (Task 4).
- Commits on the branch may be rough; the branch is cleaned up after Sven's review.

## Review Focus

1. **The page sends an argument the stricter reading now refuses** (a missing flag, a string for a number): the app
   should behave as before. Task 8's generated argument types make svelte-check catch it; Task 9's run in the exe
   exercises each edit.
2. **Enum keys in a dictionary** (`MapInfo.counts`): the key must be `unit`, not `Unit`. Pinned in Task 2.
3. **`choices` still waits for the install to open** after it moves into the table. Pinned in Task 5c.
4. **The boot script's JSON is unchanged**, including `"legacy":null` when `settings.json` exists. Pinned in Task 4.
5. **Terminal commands still run beside the queue** (`RunsAlongside`) once they come from the table, and an unknown
   name does not. Pinned in Task 5c.

The output format, which the tests pin exactly:

```ts
// Generated by tools/MoonwellEditor.BridgeTypes from the C# types. Do not edit: run `npm run types` in web.

/** The type's summary. */
export type Answer = {
  /** The property's doc. */
  name: string;
  title: string | null;
};

export type SampleKind = "unit" | "item";

export type Commands = {
  ping: { args: Empty; answer: string };
};

export type Tells = {
  write: WriteArgs;
};

export type Events = {
  changed: Answer;
};

export type ErrorCode = "noMap" | "badRequest";
```

Declarations are separated by one blank line; named types come first, sorted by name (ordinal), then `Commands`,
`Tells`, `Events` (entries sorted by name) and `ErrorCode` (in enum order). Two-space indent, `\n` line ends, no BOM,
the file ends with one `\n`. A doc is one line (`/** ... */`); none is written when there is no doc. An empty record is
`export type Empty = Record<string, never>;`.

- [ ] **Step 4: Implement `DocComments`** in `DocComments.cs`: read `Path.ChangeExtension(assembly.Location, ".xml")`
  when it exists; key `T:` and `P:` members by their XML doc ids (nested `+` becomes `.`). `OfProperty` takes the
  property's own `<summary>`, else the type's `<param name="...">`. Text: `<c>x</c>` → `` `x` ``,
  `<see cref="T:A.B"/>` → `B`, `<paramref name="x"/>` → `x`, `<see langword="null"/>` → `null`, whitespace collapsed,
  trimmed; `*/` in text becomes `*\/`.

- [ ] **Step 5: Implement `TypeScriptWriter.Write`** in `TypeScriptWriter.cs`. Walk from the roots (commands' `Args`
  and `Answer`, events' `Payload`, `ErrorCode`, `Others`), each type tagged answer or argument by how it was reached.
  For each, `options.GetTypeInfo(type)`:
  - `Object` kind → properties in `JsonTypeInfo.Properties` order by `JsonPropertyInfo.Name`. Answer side: `| null`
    when `IsGetNullable`. Argument side: optional (`?:`) when `AssociatedParameter?.HasDefaultValue == true`, `| null`
    when `AssociatedParameter?.IsNullable ?? IsSetNullable`. The CLR name for docs is
    `((MemberInfo)AttributeProvider!).Name`.
  - `Enumerable` → `T[]` of the element type; `Dictionary` → `Record<string, V>` for string keys,
    `Partial<Record<K, V>>` for enum keys.
  - Enums → serialise each value of `Enum.GetValues(type)` with the options and use the JSON text as the literal.
  - `string`/`char` → `string`, `bool` → `boolean`, numeric types → `number`, `JsonElement` → `unknown`.
    `Nullable<T>` → its `T` (the nullability is on the property).
  - Anything else (`object`, a non-collection interface) → `BridgeTypesException` with the path (`Loose.payload`).
  - Two different CLR types with the same `Name` → `BridgeTypesException` naming both full names.
  - A type reached both as answer and argument whose properties' required/nullable flags differ →
    `BridgeTypesException` naming it.
